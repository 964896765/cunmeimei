# V0.17 · 预约时间安全与运行边界

- PostgreSQL 在真正执行 `INSERT` 时用数据库的 `clock_timestamp()` 再次判断，避免排队等待后提交已经失效的预约。
- **同一用户的已有有效预约**仍可被识别为网络重试，不会因为进入提前 10 分钟的截止窗口就误认为新的非法预约。

- 商家不能在约定开始时间之后再把待确认预约变成“已确认”；不会自动转成“已完成”。
- 新增 V0.17 预约策略、真实 HTTP 接口、商家权限/时间窗口、PostgreSQL SQL 合同测试，并为 PostgreSQL 可选集成套件增加过期时间断言。

## V0.5 已有基础（历史内容）

1. **可追踪的 PostgreSQL 迁移**：`schema_migrations` 保存迁移文件名、SHA-256 校验值和执行时间；对迁移过程加 PostgreSQL advisory lock；每个文件独立事务，失败自动回滚；二次执行跳过已记录的版本；迁移文件内容被修改时阻止继续。这些能力的逻辑测试已经完成，数据库本身仍待联调。
2. **数据库结构检查与启动门禁**：`npm run db:check` 检测缺失/不一致的迁移。启用 PostgreSQL 的 API 服务在监听 HTTP 端口前执行同一检查；出错直接停止，避免对不完整的数据库接单。
3. **预约防超时确认**：PG 层商家确认预约时，更新语句额外要求 `hold_expires_at > now()`；原有唯一部分索引仍用于阻止多个用户同时占据同一服务时段。单人单资源每整点仅 1 位，待确认保留 30 分钟。
4. **预约日期使用中国标准时间**：微信预约页默认日期统一为 UTC+8，不受手机本地时区变化影响。
5. **新增测试**：迁移重复执行/失败回滚/校验值漂移单测，以及可选择运行的真实 PostgreSQL 并发预约集成测试。真实数据库测试只允许使用单独的 `PG_TEST_DATABASE_URL`，在该数据库中新建随机测试 schema，测试完删除这个 schema，不触碰现有业务表。

V0.4 的私有证照（开发版）、审核后台、服务预约、商家角色、举报处理等能力继续保留。**证照尚未完成 AV 扫描、图像解码重编码、操作审计和生产级密钥及存储管理，因此不可真实收集商户敏感材料。**
