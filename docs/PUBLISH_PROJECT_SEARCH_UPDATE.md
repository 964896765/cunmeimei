# 发布项目搜索与418项配置接入

2026-10-20。按用户提供的两张搜索参考图和逐项规划台账实施。台账作为待复核的规划输入，不视为发布或经营许可。

## 已完成并有证据

- 搜索展开占据整行。空关键词保留行业目录，输入关键词切换成全宽结果列表，显示项目名和行业/组路径；保留取消、清空、无结果反馈。
- 取消或清空恢复分类和实际滚动位置。跨行业搜索结果选择后定位到对应行业；关闭类目不加载默认表单，取消提示后保留搜索词。
- 使用名称精确、别名精确、前缀、包含、分组、行业的相关度评分；支持大小写、全角英文字母与空格组合词，按原目录顺序稳定处理同分项。
- 27行业、83组、418项目的ID和名称不变。逐项补入852条名称类别名，每项均有别名；执行852条别名回查。这里的核对是名称/分组的语义与结构核对，不等于业务资质复核。
- 每项均有明确发布配置，关联台账的建议通道、七个基础业务编码、身份和审核策略、配置版本、当前状态。没有默认兜底模板。
- 从 `classification-contract.js` 移除房产/社区等少量项目ID硬编码名单，改读共享目录配置。与迁移前43项映射逐项一致，其余375项没有新增开放。
- 现有四类居民表单（闲置、房源、社区、服务需求）的专属字段改用 `publication-fields` 组件与版本化字段合同；复用文字、数字、单选、日期和只读预览。图片与城市选择继续使用已存在的能力。
- 前后端共用字段白名单。新草稿与发布记录保存 `templateCode` 和 `templateVersion`；服务端拒绝不匹配版本，旧记录缺省版本继续兼容。现有JSONB承载这些兼容字段，无需新增业务表或修改历史迁移。
- 草稿保存、恢复、发布预览、真实提交、待审核状态及匹配草稿清理通过实际本机API验证。原六主题、导航、冻结配色和权限边界保留。

## 五阶段的真实进度

| 阶段 | 当前结论 |

| 动态发布引擎 | 现有四类表单已组件化并记录版本；七大业务的完整子模板、多选及行业特殊交互尚未全量实施 |

| 内容生态 | 保持现有已接通业务的首页、发现、搜索、详情和管理链路；没有把未实现业务伪装成可用入口，也没有自动生成地图点位 |
| 验收和开放 | 全量搜索/准入矩阵及现有链路验证已完成；418项逐业务端到端验收、真机输入法、弱网、读屏和正式准入审核尚未完成 |

因此，本轮不是“418个项目业务全部上线”。只有原来的43项映射保持可用，新业务仍须按独立模型、主体资质与服务端规则继续建设和分批开放。

## 主要文件

- `miniprogram/data/industry-catalog.json`：规范数据源；对应 `.js` 由构建脚本生成，适配微信模块加载。
- `scripts/catalog-aliases.tsv`：逐组人工整理的别名；生成器校验稳定ID顺序、条数和规划名称。
- `scripts/enrich_classification.js`、`build_classification.js`：台账核对、别名和配置生成、强校验。
- `miniprogram/utils/classification.js`、`classification-contract.js`：搜索与共享准入合同。
- `miniprogram/utils/publication-schemas.js`、`components/publication-fields/`：现有模板字段与版本。
- `miniprogram/pages/publish/index.*`：展开/清空/收起、目录恢复、全宽结果、字段组件和预览。
- `backend/src/rules.js`、`product-repository.js`、`account-drafts.js`：原业务准入、共享字段白名单、分类与版本校验。
