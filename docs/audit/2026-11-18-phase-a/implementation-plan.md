## D · P1 业务与体验，含 176 项插画

顺序：补真实反馈与举报汇总 → 搜索/频道筛选与分页稳定性 → 行业有效期/到期状态 → 微信订阅（有真实配置才开放）→ 实测性能与缓存重验 → 视觉资源全覆盖。

插画可以与本地业务修复分批进行，但不能取代 P0 验收。输入使用 [176 CSV](illustrations-176.csv)，原制作链为 `scripts/render_category_scenes.py`、`category-scene-specs.json`、`build_category_scenes.js`。每类以真实业务对象设计，不通过同一模型只换颜色凑数；透明背景、材质/光向/投影与已确认房产卡片统一。宠物/亲子已调整资源继续查语义重复，不覆盖满意的既有房产图。

每批交付：分类 ID → 场景 → 图片映射、前后接触表、实际页面截图、尺寸/字节/哈希/加载结果。完整替换 176 个临时图标后，仍逐项复核原 72 张初稿。更新 `utils/category-art.js` 与 scenes 映射，既有五个房产覆盖不误替换；不改变分类业务字段。

包体：每批重新微信编译量包，确保主包/分包/总包满足当前平台限制；超限时先缩图、WebP 压缩、排除源码与重复资源。需要远端托管时先确定真实可用存储、合法域名与缓存/离线降级，再调整加载方案，不写假 CDN 地址。不能拿源码估算冒充编译上传结果。

性能：使用代表性数据测首屏、API p50/p95、内存、图片处理峰值、弱网、EXPLAIN 查询计划，再决定索引与缓存；低资源服务器保持单体和轻量部署，不引入无必要微服务/Kubernetes。
