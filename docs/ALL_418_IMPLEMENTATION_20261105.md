# 418项逐项业务闭环补齐 · 2026-11-05

本轮直接扩展原发布、行业、联系、商家、预约、积分、隐私和运营模块，保留既有微信登录机制及PRISM GLASS六主题。418项逐项执行适用的隔离PostgreSQL与HTTP流程，不以目录数量或代表模板通过代替完整验证。

## 范围与行为

| 项目范围 | 本轮闭环 |
| --- | --- |
| 43项居民信息、308项双方处理类行业项目 | 原内容发布审核、展示查询、私密申请、接受联系、原条款快照、双方时间约定、完成请求及对方确认、取消、反馈、运营争议处理、本人回查和结束 |
| 其中198项可预约服务 | 项目专项资格、独立商家入驻核验、显式连接负责商家、独立服务内容审核、时段占用及竞争、商家确认、预约业务进度、完成同步、取消及停止新预约 |
| 67项资讯、官方来源指引与持牌目录 | 来源和资格审核、展示查询、禁止交易申请、内容纠错、运营答复、更新重新审核、结束及本人记录；不虚构交易或诊疗、金融产品等能力 |
| 活动 | 复用原活动时间与人数限制；结束前不能确认参与完成，不提供另行修改时间的按钮；仍只支持免费报名 |

“我的”继续保留积分中心与服务中心，新增业务进度统一归入服务中心。从原申请、站内联系、本人预约及商家预约均能进入同一处理记录。通知新增业务进度分类，并导向本人具体记录。旧私密请求、换账号、拒绝/过期、未提交说明和待核对操作均保留相应保护。已结束且没有进度的联系不提供新建入口，已有进度保留历史入口；争议按完成或取消结案的结果明确展示。

## 业务和数据约束

- 来源必须是本人已接受且有效的联系，或具备负责人、已确认/已完成的原预约。第三人不能读取或写入。关联服务预约保留原项目、原信息与供给版本；原商家单方完成的历史预约显示“原预约已完成”，不冒充新增的双方确认。
- 时间、完成及取消都按双方权限处理；活动和库存预约时间以原模块为准。版本、幂等编号及冲突检查在服务端执行。
- 业务事件只追加；本人导出只含本人创作的事件，去掉对方原申请与答复。未结束进度会阻断注销，并给出中文处理原因。
- 运营处理争议同步结束原联系/申请或适用预约，不留下永久无法注销的未处理事项。
- 原行业内容改版、下架、专项资格失效或商家/成员撤权后，关联服务的公开详情、图片、列表、地图、时段与新预约统一失效；历史预约与原服务版本保留。
- 相同来源的服务发布后，列表合并原行业卡片；服务的城市、区县和项目按原来源查询，不依靠虚构地图位置补齐筛选。
- 新预约/确认使用数据库触发器及行锁作为最终检查；明确失败的预约编号持久化，资格恢复后同一编号仍返回原拒绝。
- 后台服务独立审核及业务争议仅运营角色处理，沿用CSRF、审计和统一待办；原快捷服务审核不能绕过关联项目复核。
- 没有自动读取头像、昵称或手机号，没有新增传统密码登录，没有公开双方说明或默认公开号码。
