## 功能及权限

| 环节 | 实际实现 |
| --- | --- |
| 创建与草稿 | 微信账号绑定、独立创建编号、重复创建重放、版本冲突保护 |
| 纪念资料 | 姓名、可选生卒日期、纪念照片、生平与创建人维护的追思文字 |
| 授权材料 | 独立私有文件目录，材料读取需要本人或核验权限，后台访问写入审计 |
| 核验 | 核验员查看对应逝者资料及授权材料，填写依据，独立确认授权有效性 |
| 内容审核 | 运营审核文字、照片使用范围及公开范围，独立于授权核验 |
| 提交留存 | 用户、纪念馆、资料版本、授权编号、须知版本、确认时间及提交快照 |
| 公开访问 | 专区开放、账号有效、审核通过、申请公开及当前授权有效共同控制 |
| 统一搜索 | 全频道关键词搜索展示符合公开条件的纪念馆，行业及业务筛选保持相应业务范围 |
| 寄托思念 | 免费献花、点烛和三条固定祝福，同一账号同馆同类型每日一次 |
| 隐藏与撤权 | 详情、搜索及公开照片接口同步停止访问 |
| 资料修改 | 重新进入草稿并停止公开，身份资料变化后核对授权关联 |
| 删除 | 清空当前纪念资料并停止公开，保留必要的提交、核验、举报与审计档案 |
| 举报及权利请求 | 登录提交、本人管理页查看答复、运营记录处理结果及隐藏决定 |
| 个人数据 | 独立本人数据导出，现有注销流程会停止其纪念馆公开访问 |

自由评论、访客自由追思文本、私信、现金支付、打赏及排行榜均按首版范围关闭。创建人维护的追思文字随纪念资料一起审核。

删除纪念馆与个人信息永久清除采用各自的处理流程。目前数据库及私有文件中的核验、提交与审计档案继续保留，正式运营前需要确定保留期限及清理执行规则。

## 数据库与回滚

新增迁移 `034_memorial_module.sql`，包含七张独立表、公开资格视图及纪念照片引用保护触发器。001至033迁移文件沿用已有版本。

升级前已有74张表、1340行数据。备份恢复比对及新增迁移后的原有数据比对均通过。恢复演练数据库已清理，备份留在源码目录外。备份文件位置与SHA-256见 [local-upgrade.json](local-upgrade.json)。

紧急停止公开时，将 `MEMORIAL_PUBLIC_ENABLED=false` 并重启对应服务。随后检查 `/api/v1/config` 中的功能标识、纪念馆公开详情与照片返回状态。客户端重新加载配置后隐藏发布页入口。

本地服务可用以下命令重启。

```powershell
./scripts/start_local.ps1 -Restart
```

视觉回退可从 `8a010f9` 恢复发布页、搜索页及主题接入文件，并在小程序路由表中撤回新增页面入口。数据库、034迁移文件及其识别逻辑应与当前后台一起保留，避免已应用迁移与旧版迁移清单不匹配。数据库整库恢复需要在维护窗口先验证备份、核对新增资料与恢复目标，再制定恢复步骤。
