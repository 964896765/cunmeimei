# 阶段 1 P0 安全整改

日期为 2026-11-10。整改分支为 `remediation/v1-stage1-security`，原始基线分支为 `baseline/original`。

阶段 1 代码与隔离数据库安全验收通过，严格 PostgreSQL 门禁 587 项通过，P0 专项最终复跑 5 项通过。

## 已实现

- 所有 `/admin/api/` 业务路由在分发前统一检查权限和 CSRF，未登记的方法与路径默认拒绝。
- 新增独立 superadmin 凭据，沿用 operator、verifier 两类账号。会话权限由服务器配置签发。
- 隐私请求与消息、举报证据分别采用 privacy、evidence 独立权限。
- 工作台按角色过滤任务及计数，队列对证照和举报说明脱敏。
- 核验员只可读取待核验房源关联的内容图片，证照走独立核验接口。
- 后台访问记录包含角色、会话审计 ID、方法、路径与授权结果。已认证的越权请求记录拒绝原因。
- 缺失、拼错 NODE_ENV 被阻止，`npm start` 强制生产模式，生产 preflight 同步检查。
- 生产要求明确关闭开发登录、独立角色密码、有效手机号加密密钥与现有生产配置。
- 真实启动入口传入已校验的法律主体和隐私联系信息。
- 新提交无论模板版本都执行当前必填校验。
- 编辑在账户和信息锁保护下校验最终字段，分类和图片采用独立的替换标记。
- 既有无分类记录可继续读取，编辑时必须补齐当前必填字段。已有分类关联不能清空。
- 测试并发受控，严格 PostgreSQL 门禁包含 P0 专项测试。
- 分类全链路测试支持较慢的 Windows/Docker 环境，超时或取消时报告标为 incomplete。
