# 村美美 V2 账号与认证架构检查

检查日期为 2026 年 11 月 23 日。范围为当前小程序、API、PostgreSQL 迁移、隐私文本和既有验收记录。生产短信模板、真实号码归属以及生产库状态需单独核验。

## 已有能力

| 范围 | 代码现状 |
| --- | --- |
| 微信登录 | 小程序已用 `wx.login` 和显式条款确认。API 用微信凭证换取 OpenID，再通过 `app_identities` 找到同一个 `app_users.id`。账号和资料填写分开。 |
| 会话 | Token 随机签发并以摘要存储。现有到期、退出、注销后的失效和客户端防跨账号重放逻辑已存在。显式轮换续期和登录结果审计尚缺。 |
| 手机号 | 微信授权按钮和后端授权码校验已存在。手机号加密，查询用独立摘要，绑定和公开逐条授权分开。号码摘要还没有跨账户唯一归属保护。 |
| 业务权限 | 浏览和搜索允许游客，收藏及举报需登录，发布、联系和入驻已有不同程度的准入及审核。现行联系门禁要求手机号，常规私信与高风险私信还需区分。 |
| 注销和隐私 | 已有隐私授权、拒绝后浏览、个人数据请求、人工注销执行、会话和号码清除及保留范围说明。现有手机号授权记录和同意版本可复用。 |
| 短信 | 在当前代码、依赖、环境变量名和迁移里未发现可调用的发送与验证实现。历史审计记载了阿里云和一个历史签名，无法由此确定产品类型、模板状态或正式发送能力。 |

以上依据 [微信登录提供端](../backend/src/wechat-login.js)、[服务端路由](../backend/src/server.js)、[账号存储](../backend/src/pg-repository.js)、[手机号与业务准入](../backend/src/trust-repository.js)、[注销与导出](../backend/src/account-lifecycle.js) 和 [前次生产审计](audit/2026-11-21-production-v1/README.md)。

## 增量改造边界

1. 延用 `app_users` 的 UUID 和已通过验收的微信登录入口。UnionID 有值时补记，发现歧义时由运营核验，禁止自动归并账号。
2. 新会话可以在到期前受限轮换，轮换后旧 Token 失效。注销或账号受限时停止续期。登录审计只记录分类、时间、渠道、风险状态和结果。
3. 在 `verified_phones` 上增量加固新写入，按号码摘要串行核对归属。存量重复保留供人工核查。验证时间与授权状态继续由现有手机号记录维护。
4. 短信复用经确认的发送端，验证码校验由服务端负责。持久化挑战用于目的绑定、错误次数、一次消费和号码／账号／网络来源限额。未配置真实发送端时保持关闭。
5. 短信绑定与换绑只能修改已登录的统一账号。换绑需要验证原绑定号码或通过既有身份核验。账号找回应有独立的身份复核条件，手机号本身不能触发开户或自动移交微信账号。
6. 发布和入驻复用现有审核，常规文字私信沿用既有风控，风险路径追加手机号验证。官网与小程序的隐私说明按真正开放的功能同步。

实施后的验收分别记录使用隔离 PostgreSQL 和服务夹具的结果，以及依赖真实微信、短信与生产配置的结果。
