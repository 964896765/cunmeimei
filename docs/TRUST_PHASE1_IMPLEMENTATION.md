# 村美美：身份、业务核验与联系保护第一版

2026-10-20。复用现有后端、数据库和运营后台。本轮不是上线审批或外部服务开通证明。

## 用户与管理流程

- 匿名浏览/搜索不增加登录门槛；收藏与个人资料沿用登录保护。
- 发布项目选择后检查真实手机号状态。需要验证时显示项目名称和“微信授权手机号”；成功使用 `redirectTo` 直接进入原项目表单；拒绝、失败或账号切换不跳转，也不伪造成功。
- 发布表单增加逐条联系设置：公开电话默认关，陌生人联系默认开；开启电话前单独确认，不能任意填写第三方号码。
- 在账号与安全中查看四项独立状态，在我的发布中撤回公开电话或调整陌生人联系权限。
- 信息详情按实际核验记录显示手机号验证、业务材料及内容审核状态，始终不显示虚构的身份认证。审核通过不等于平台保证真实。
- 联系申请接受后进入真实文字会话；关联信息结束后不接受新申请，已有会话由双方结束/屏蔽控制。纯文字第一版不提供图片、视频、文件发送。
- 风险消息暂缓送达，供人工检查、决定是否放行；不根据关键词永久封号。双方均可屏蔽、结束或举报。用户可对自己的违规处置提交申诉；通过申诉只解除对应当前限制，不覆盖后续新处置。

## 人工业务核验

核验角色只记录真实核查结果、材料工单、有效期和范围，不收集新身份证照片、号码或将其标为实名认证。以下三项分开：

1. `housing` 或已存在的分类 ID：该账号的对应分类发布资格。
2. `publication:信息ID`：只核验本条信息的材料，需属于同一发布者。
3. 内容审核：必须实际检查文字、每张图片和适用材料，按读取时的修订版提交审核。

房源通过分类资格后可以提交待审核；公开前必须完成该房源当前版本的单独材料核验。材料核验既不解锁未开放分类，也不会继承到另一条房源/闲置信息。

后台仍位于 [现有运营后台](http://127.0.0.1:3101/admin)，增加用户状态、业务资质、风险、申诉、核验日志和418项只读规则。普通运营与独立业务核验采用不同服务端密码。当前是两个管理角色，不声称已具备多管理员实名账号管理系统。

## 服务端保护

- 新增迁移 `016_trust_and_contact_safety.sql`、`017_publication_material_revision.sql`，保留原用户、草稿、图片与信息，不把旧记录批量标为已认证。
- 手机号 AES-256-GCM 加密，匹配使用 HMAC，掩码供本人和授权运营查看；密钥只存服务端。重新绑定会使旧信息上的公开授权失效。
- 新用户（前7天）每日发布最多3条、主动联系最多3次；普通账号10条/10次；可疑账号进一步限频。计数和写入在持有账号锁的事务中检查，重复提交不会重复创建。
- 严重限制须人工确认、理由和有效期，最长90天；不对普通用户公布内部风险分值。已验证号码的限制关联用于提示人工复核，不建立公开信用分。
- 重复文本、图片哈希、外部联系和资金/验证码词形成风险提示；图片外部内容检测未接通，必须人工检查。未把规则信号当作事实认证。
- 私信只对会话双方开放；消息幂等、服务端限频；举报证据读取和人工处置留审计。会话使用轮询并显示最近50条，不宣称为完整 WebSocket 即时通信系统。
- 后台沿用独立会话、HttpOnly/SameSite Cookie 和 CSRF；敏感商家材料及核验操作再按角色授权，普通运营仅见受限摘要。

## 服务端配置

`backend/.env.local` 已准备独立 `VERIFICATION_ADMIN_PASSWORD` 和 `PHONE_ENCRYPTION_KEY`，未在聊天、客户端或文档中输出值；已有设置未覆盖。正常运营密码仍为原 `ADMIN_PASSWORD`。生产部署应分别通过安全配置管理保存，勿将密钥放入小程序。

- `WECHAT_APPID`、`WECHAT_SECRET`：沿用真实微信服务配置，用于微信登录与手机号授权校验；未配置则手机号授权显示未开通。
- `PHONE_ENCRYPTION_KEY`：32字节 Base64 密钥；丢失或直接更换会影响既有号码解密，不能当作普通配色配置随意替换。
- `VERIFICATION_ADMIN_PASSWORD`：独立业务核验角色凭证。
- `PLATFORM_PUBLISH_APPROVED`、`PLATFORM_CONTACT_APPROVED`：生产环境在实际核实主体和服务类目后才能设为 true，不代表程序自动取得许可。
- 合规身份服务尚无接入配置，身份认证始终未开通。没有人工“实名已认证”或人工手机号验证通道。
