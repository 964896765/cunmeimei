## 本轮修复

1. **上传资源限制**：同一 Node 进程最多接收2个普通图片上传、执行1个图片处理任务；超额立即返回503 `UPLOAD_BUSY`，不排队持有更多图片。HTTP读取与图片处理分别有容量限制，成功和异常都会释放名额。所有Repository实例共用处理限制。单图解码由3600万像素收紧至1600万像素，继续保留2MB请求限制、JPEG重编码及缩略图。
2. **上传配额顺序**：在账户上传锁和事务内先检查每日30张配额，再解码、插入。超额用户不能继续消耗图片解码资源；解码失败回滚事务。高像素手机照片可能需要先压缩，错误文案已说明1600万像素上限。限制只针对当前普通内容图片入口，不代表商家私有证照生产上传已开放。
3. **数据库连接恢复**：监听PostgreSQL连接池的空闲连接错误，记录固定事件名而不打印驱动异常正文。真实终止本次隔离测试连接后，API进程继续运行且Repository重新连接成功。通用SQL执行超时、生产故障告警及网关限流仍须部署验收。
4. **发布检查漏洞**：同时检查共享与私有项目配置，私有配置关闭域名校验不能再被忽略。正式API地址拒绝IPv4/IPv6、数字形式IP、本地域名、单段主机名及无效DNS标签；仍须HTTPS且不能带账号密码、路径参数等。这是格式检查，不验证DNS、备案、证书或微信合法域名登记。
5. **生产配置预检**：新增 `DATABASE_URL` 必填及PostgreSQL URL格式检查，拒绝缺失、错误协议、缺少数据库名和fragment的配置，不在报告中输出连接串。
6. **检查工具维护**：历史完整性脚本适配已经存在的21页，并继续核验原始15页、五导航、冻结颜色和001–005迁移校验和，没有放宽为任意路由。新增 `npm run check:prelaunch` 汇总JS语法、页面/WXML、历史完整性、业务冒烟、非PG回归与发布配置，保留逐项结果；子进程清空业务与测试DB URL。
7. **开发依赖安全**：完整审计首次发现12条依赖链告警，其中含3条critical、2条high。保留automator 0.13，锁定其debug 4.4.3、Jimp 1.6.1，并覆盖Zod至4.6.6；更新锁文件及Node最低版本为20.9，与Sharp要求一致。Jimp新旧导出通过 `scripts/devtools_image_compat.js` 适配，供当前连接工具使用；生成PNG和JPEG二维码，经automator实际解码验证。兼容范围是项目使用的二维码读取接口，不声称验证全部Jimp编辑插件。按锁文件全新安装及最终完整审计均成功，0条已知漏洞。
8. **微信验收结果可靠性**：预约验证脚本开始时使旧结果失效，失败写明失败结果，失败清理后返回首页；增加显式 `--no-screenshots` 模式并在报告中记录，避免把历史成功JSON误认为本次成功。
