# 上线前底层能力加固记录

日期：2026-10-30。继续在原工程增量修改，保留小程序页面结构、五导航与既有配色。本轮没有部署生产，也没有改动已有开发数据库。附件作为产品设计参考；其中“阶段0只审计”的历史任务描述没有替代本次用户明确要求的开发工作。

## 本轮实现

### 一个入口处理审核任务

后台 `/admin` 默认展示“我的统一待办”，其余管理模块折叠收起。待办按风险优先、同级提交时间排序，支持类型筛选、每页20条、准确总数和翻页。读取使用同一数据库快照，不会因旧模块100条截断而漏掉后续任务。

内容、重复/风险提示、单条房源资质、商家申请、举报、申诉、数据权利请求、超过48小时未处理的联系申请、服务审核汇总到这里。任务详情按需读取并留审计。内容、房源材料、商家核验、举报、申诉和数据请求可在本入口操作。联系超时仅提示待办，管理员不能替用户同意联系。

保留运营审核与业务核验的权限分离：经营者可负责两个角色的最终判断，普通运营账号仍不能读取证照私有材料或签发业务资质。没有把普通用户、商家成员与后台管理员权限混在一起。

新增紧急下架接口，要求后台会话、CSRF与至少8字的非敏感处置原因；下架写入审计并复用现有公开有效性规则。系统风险信号不自动等于最终审核结论。内容编辑再次生成风险提示，补上修改正文后的预审遗漏。

### 电话披露与撤权

修复普通详情接口在单条授权后直接返回明文手机号的问题。现在详情始终返回空的 `publicPhone`，另以 `phoneAvailable` 表示是否可以申请查看。小程序只在点击拨号时调用专用接口，号码不写入页面数据或全局状态。

专用读取重新检查账号及联系限制、手机号验证、信息已公开且未过期、地区有效、当前单条授权、绑定号码版本和双方屏蔽关系。每账号每小时最多20次成功读取；配额在账户锁下计算。返回前写入访问事件，不记录真实号码。撤销授权、解绑或更换号码后，新的读取立即失效。

新增逐次授权/撤回证据表，保留文案版本、号码版本引用和时间；禁止修改或删除历史证据。旧授权此前没有完整事件历史，本迁移不伪造历史授权记录；旧表保留的授权时间和号码版本仍在。

服务器内部异常日志不再直接打印数据库异常正文，避免异常文本带出用户输入。详细生产告警、日志保留与外部通知仍须部署配置。

### 积分记账内核

新增独立账户、不可变账本、冻结记录和默认关闭的规则表。服务支持发放、冻结、释放、消费、冲正和人工调整；所有服务层余额变化与账本、冻结状态、审计在同一事务提交。幂等键同时核对请求内容，不能将同一键换成另一笔业务。账户行锁防止并发超支，冲正保留原始账本且每笔最多一次，提供全账余额核对。

**这是内部记账能力，尚未开放用户积分或兑换。** 贡献事件接入、24–72小时延迟结算、互刷关系判定、规则配置界面、过期冻结自动释放及积分用户界面尚未完成。没有把测试发分当作线上奖励，没有开放充值、提现、转让或现金兑换。

### 广告库存与审核内核

新增广告主档案、人工核验有效期、广告版本审核、地区/广告位/起止时段库存、排期记录和不可变档案。未核验广告主不能批准广告；审核必须确认文字、图片和证明文件。排期在库存行锁内确认，与积分冻结消费保持同一事务；最后一个库存并发只允许一笔成功。投放查询只返回当前有效、已排期且主体核验有效的活动，并显式返回“广告”标签；暂停、过期、落地信息失效后不再投放。

**这是内部审核、排期及查询能力，尚未开放广告产品。** 用户申请与兑换API、套餐价格校验、时段管理界面、素材投放前端、曝光点击去重与反作弊、取消退款和档案保留周期管理尚未完成。未开放付费或商业广告投放。

### 备份与恢复演练

新增 `backend/src/database-recovery.js`：原生 PostgreSQL 工具或指定 PostgreSQL 工具容器执行自定义格式备份；凭据通过环境变量传递，不出现在命令参数和日志中。文件以独占方式创建，SHA256分块计算，避免把大备份一次性读入内存。

恢复只允许 `restore_drill_*` 命名的空数据库，先验证校验和、再检查目标为空，使用单事务恢复，不使用清库参数。生产恢复前需先恢复到新库，核对后单独执行流量切换。

隔离容器已真实完成备份、恢复和逐表内容哈希比较，覆盖49张表；同时验证拒绝覆盖已有数据、拒绝损坏备份。演练库、临时备份、容器、网络和卷结束后清理。**这不代表已备份真实生产数据或设置定时备份。** 私有证照文件、加密密钥、备份加密、异地保留和生产告警仍需配置。
