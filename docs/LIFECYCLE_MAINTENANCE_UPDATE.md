# 账号生命周期与后台维护提升

日期：2026-10-30。继续原工程开发，保留页面数量、五导航和现有配色。新增021、022迁移，001–020未改写。没有修改持久开发库、部署生产或开启积分广告用户产品。

## 账号注销从申请到执行

“我的 → 个人数据”新增独立的“账号注销”申请类型。它与定向“数据删除”请求分开，不能把删除草稿等请求解释为注销整个账号。申请时读取当前保留范围，经过单独确认后记录文案版本；执行前可以撤回。

后台统一待办读取申请后，可标记处理中、拒绝并说明，或执行注销。普通“记录答复”不能代替注销执行。执行需要运营审核角色、有效后台会话、CSRF、当前请求版本、明确确认和不含敏感号码的核验原因；业务资质核验角色不能执行。

执行在同一事务内：

- 检查商家所有权交接、未完成预约、冻结积分和未结束广告；尚有事项时返回明确阻断，不擅自销毁业务权益。
- 关闭待审/公开信息、单条电话和陌生联系能力，结束联系会话，撤回尚未开通的商家申请和广告申请。
- 清理原始登录身份及全部会话、绑定手机号、昵称简介城市头像引用、账号草稿、收藏、个人偏好等；停止商家成员权限。
- 保留必要审核与业务档案、积分账本、授权事件、处置证据及匿名化后的账号关联，不通过直接改余额或删除账本实施注销。
- 原始登录标识清理前生成单向身份指纹；原身份再次登录不会自动创建新账号或恢复原账号。当前没有自动重新注册/恢复流程。
- 写入不可变执行记录和管理员审计，成功后才将请求标记为已执行答复。并发重复执行只落一次记录。

新增账号行锁与数据库写入检查，防止注销之前已经鉴权的迟到请求重新创建会话、发布、头像、草稿、手机号、收藏、预约等。已关闭个人资料也不能被迟到的编辑覆盖。

这实现了**账号关闭与主要资料清理**，不等于删除全部历史个人数据。历史正文/消息、图片及证照文件、审计与业务档案仍受保留策略约束；生产保留期限、到期清理和定向删除执行器尚未完成，继续作为上线门禁。

## 用户自己的数据导出

新增鉴权接口 `GET /api/v1/me/data-export?section=...&cursor=...`，固定白名单包括资料、发布、草稿、收藏、联系、本人发送的消息、积分账本、数据请求和电话授权事件。每页最多50条，游标分页，每账号每小时最多120次读取，记录导出事件。

接口不接受任意用户ID或表名，不返回登录凭据、原始登录标识、加密手机号、真实号码、他人写出的消息或内部风控证据。此导出是逐页读取的个人资料视图，不是跨页一致性数据库快照，也不包含图片二进制或全部业务档案；更多范围仍可提交数据访问申请。

小程序“导出我的数据”将内容临时写入本次操作独占的JSONL文件，由用户在微信原生文件保存/分享界面选择去向。完成或取消后尝试清理临时文件，清理失败明确提示；账号切换或离开页面后停止读取和分享。较大数据或不支持文件分享的微信版本提示走数据访问申请，不把部分导出冒充完整导出。

实际微信原生文件保存/分享、取消及文件清理仍需真机验收。本轮通过JS与原生接口适配器验证，未宣称真机已通过。

## 自动维护与统一异常待办

PostgreSQL服务正常启动后，每分钟运行维护任务：释放过期积分冻结、结束已到期广告并归档、核对积分账户与账本。每次冻结释放仍通过不可变账本和事务提交；并发工作实例采用数据库任务锁，处理批次有上限，重复运行不重复发放或退款。

任务记录开始、完成、最后成功时间及连续失败次数。失败只记录固定异常代码，进入后台“统一待办 → 系统异常”；运营角色可从同一入口重试。核对异常只报警，不自动改余额。恢复成功后异常待办自动结案，保留任务及告警记录。数据库完全不可用时只能输出不含敏感信息的错误，外部告警接收渠道仍须生产部署配置。

健康接口：`GET /admin/api/operations/health`；重试接口：`POST /admin/api/operations/run`，后者要求运营角色和CSRF。关闭服务时等待在途维护结束，再释放连接池。

## 广告取消与时间边界

修复了排期重试中先读取已有排期、后检查所属账号的问题。现在必须先确认活动属于当前用户，才能读取或重试排期。

内部广告服务新增开始投放前的取消：库存锁、消费冲正、取消标记与档案记录在同一事务提交。历史排期保留，取消的库存可供后续活动使用；并发重复取消最多退款一次。已开始活动不能走“开始前全额退款”路径，须运营核查。排期确认和取消取得库存锁后重新使用数据库当前时刻检查开始时间，防止等待锁跨过开始时间后仍错误确认或退款。

以上仍是内部服务能力，没有公开用户广告申请/套餐/兑换接口。广告定价、投放前端、统计、完整退款规则与生产档案周期仍待完成。
