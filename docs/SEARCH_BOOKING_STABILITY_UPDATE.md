# 搜索、发现与预约稳定性补强

日期：2026-11-01。此次继续改进本地小程序，没有连接目标服务器、修改后端业务实现、执行数据库迁移、删除现有业务数据或改变生产配置。

本报告记录搜索/预约阶段；2026-11-02的详情、联系与聊天补强及最新回归结果见[后续报告](CONTACT_INTERACTION_HARDENING.md)。

## 已完成

### 搜索与本机记录

- 清空历史的确认框绑定发起时的账号与存储键；切换账号后返回的旧确认不会清空另一个账号的记录。
- 读取、保存或清除本机搜索记录失败均有独立提示；记录故障不阻断搜索请求，不伪造成功清除，也不清空用户其他存储。
- 搜索结果、热门词及配置请求检查用户、会话、开发测试模式和浏览城市，旧上下文结果即使在下次onShow前返回也不会应用。
- 旧配置返回时不会重启已经被新提交替换的搜索；连续点击重试不会重复发起同一在途页面请求。
- 下一页失败保留已加载结果，重试仍读取失败页；达到当前支持的分页边界后停止继续请求，提示缩小地区或条件，不声称已展示全部匹配项。

### 发现页

- 同样拒绝旧账号/城市/测试模式的晚到结果，并处理分页上限和重复重试。
- 定位结果在应用排序前验证数值及经纬度范围；失败时保留现有列表、原排序和排序面板，不清空内容或静默改用其他筛选。
- 本次没有新增定位调用，仍只在用户主动选择距离排序时请求；没有修改手动选择的浏览城市。

### 我的预约

- 增加独立加载、错误和重试状态；请求乱序、切换账号、页面卸载不会回填旧列表。读取失败保留已有记录，不显示成功空状态。
- 取消按钮在确认和提交期间锁定；确认返回时再次检查账号及最新预约状态，不能取消不存在或已不可取消的记录。
- 如果提交结果不明确，显示“取消结果暂未确认”，暂停再次取消，要求先刷新状态。测试模拟了“服务端已取消但返回503”的情况，刷新后正确确认已取消，全程只发出一次取消请求。
- 服务端明确返回取消成功后立即呈现已取消；即使后续列表刷新失败，也不会恢复为可取消状态。
- 时间统一标明北京时间；无效或缺失时间显示“时间待确认”，避免整个列表读取失败或显示1970年。
