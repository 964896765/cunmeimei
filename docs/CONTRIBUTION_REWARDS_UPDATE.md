所有普通贡献合计每用户每天最多20分。额度按北京时间的事件采集日计算，有效期奖励在维护任务首次记录符合条件时占用当天额度，不按到账日重新增加额度。拒绝、取消的事件仍占用原日额度，防止通过反复撤回与重试回收配额。

发布审核、收藏插入和联系接受通过数据库触发器在原业务事务内记录贡献事件，失败不会留下半笔事件。仅记录有效且非测试的公开信息，作者自己的收藏不记奖励，未接受联系不记奖励；浏览和广告点击不记奖励。同一规则、同一信息、同一互动用户终身至多一个贡献事件，取消后再收藏不能重复创建奖励。

有效期奖励基于最近一次审核后持续有效的时间，编辑重审重新计算有效时间；每条信息的7天/30天奖励各至多一次。规则启用前已审核的旧信息不会因开启规则而追补有效期奖励。首次审核历史另存不可变记录：历史审核日志与历史公开状态分别标明来源，缺失准确历史时间时不伪装成新发生的审核。关闭规则时发生的首次审核也会留标记，日后编辑重审不能冒领首次奖励。

## 观察期、规则快照与结算

每笔事件保存规则版本、金额、限额、观察期、信息版本和来源引用，这些来源字段禁止覆盖或删除。默认观察期48小时，后台可配置24–72小时。

观察期内不增加可用或冻结余额，只显示为待结算事件。维护任务到期后重新检查信息公开状态、有效期、地区、审核版本、账号状态，以及收藏是否仍在、联系是否仍有效、是否屏蔽等。失效事件取消；事件有效且没有未复核风险时才在同一事务内追加发放账本并标记结算。并发维护、重试和重复事件不重复发分。

规则调整不重算旧事件。**关闭规则只停止新采集，已排队事件继续按原规则快照和实时风控复核。** 后台保存规则时要求变更原因与当前版本，保留不可变规则历史和审计记录；不能把“关闭”理解为清空旧待结算任务。

账号注销会取消其作为贡献作者或互动人的未结算事件。已到账的合法历史贡献不会因为普通取消收藏、编辑、结束展示或注销就被一概扣除；确认违规后的冲正另行执行。

## 风控与人工工作台

以下信号进入原有统一待办的“贡献积分复核”，不自动等同违规：

- 当前共用号码或180天内共用号码历史，比较只使用HMAC，不向后台返回真实号码。
- 双方近期相互收藏/联系，新账号短时间跨多个作者互动。
- 互动人或贡献作者号码未验证、账号风险、信息中尚未复核的风险内容。

单纯“图片需要人工审核”提示不再次阻断已经完成内容审核的普通奖励。仍有严重行为限制的账号不能通过积分复核强行放行。运营可在原位读取账户与账本、写明证据后允许后续结算或拒绝；业务核验角色不能改规则或复核积分。

人工放行只覆盖当次核对过的风险信号。换绑号码后发现新的历史共用号码信号，或之后出现新的账号限制，会重新进入复核；不会沿用过时的人工放行。复核可能超出观察期，24–72小时不是固定到账承诺。

## 核实违规与账本冲正

已结算贡献关联的信息举报被确认违规时，维护任务追加冲正账本，原始奖励不删除。运营也可对具体贡献事件以当前版本、明确违规确认和原因发起冲正。

余额不足时不制造负可用余额、不直接改账，事件转为“待冲正”并留在同一待办；余额恢复后可重试。并发重试最多产生一笔对应冲正。普通手工余额调整另走运营专属接口，要求唯一请求标识、增减方向、工单、原因和审计；同一请求改金额会拒绝。

奖励申诉、误判后的恢复发放和用户端完整积分工作区尚未完成，所有新规则默认关闭；这些仍是开放用户积分产品之前必须补齐的门禁。当前小程序“积分与推广”仍保留未上线提示，没有冒充完整积分兑换产品。

## API 与后台入口

本人只读接口：`GET /api/v1/points/account`、`/ledger`、`/rewards`；必须登录，只返回当前账号。`GET /api/v1/points/rules` 返回规则和限制说明。奖励记录、规则版本也纳入个人数据导出。

管理端规则：`GET /admin/api/points/rules`、`POST /admin/api/points/rules/:code`。统一待办中的复核和冲正分别调用 `POST /admin/api/points/rewards/:id/review`、`/:id/reverse`。规则表单位于原后台折叠的辅助工作区，不新增用户页面。

管理端账本读取 `GET /admin/api/points/users/:userId` 记录访问审计。人工调账 `POST /admin/api/points/users/:userId/adjust` 使用 `requestId`、`debit`、`amount`、`ticket`、`reason`，要求运营角色与CSRF；没有直接修改余额的接口。
