# dgqfl.xyz 官网部署与回滚

V1.1.1 的历史上线核验详见 [部署与回滚命令](production-v1.1.1/COMMANDS.md) 和 [上线前验收报告](production-v1.1.1/REPORT.md)。

部署目标为阿里云现有 Nginx 上的独立静态站点。主域使用 dgqfl.xyz，www 统一跳转到主域并保留路径及查询参数。生产执行须按用户要求先取得人工确认。

配置模板位于 [Nginx 站点配置](../../infrastructure/nginx/dgqfl-website.conf.example) 和 [日志轮转配置](../../infrastructure/nginx/dgqfl-website.logrotate.example)。

## 制品与服务器核验

在本地执行 `npm test --prefix apps/website` 与 `npm run package --prefix apps/website`。release 中的 `*-deploy.tar.gz` 包含静态归档、静态归档的 SHA-256、Nginx 与 logrotate 模板和本说明。公网静态目录只装载内层静态归档，外层归档也附有 SHA-256。

通过已确认的服务器访问方式核对以下内容，再准备最终配置差异。

- 核对根域和 www 的权威 DNS 解析目标、当前站点归属、服务器 OS、CPU、内存、磁盘、Nginx 版本和实际启动方式。
- 确认现有 Nginx 的 http 配置加载路径、启用站点名单、默认虚拟主机和可用的 80/443 监听。避免在另一处已存在这两个名称的配置。若根域已有生产站点，先确定如何接管并记录恢复路径。
- 验证现有证书的完整链、有效期、域名覆盖和续期方式。HTTPS 的 www 跳转也要求 www 证书可用。模板中两处 fullchain 和密钥路径须替换为现场核验的实际路径。如果根域和 www 分别使用证书，则分别填入对应站点。需要 IPv6 时，根据实际监听和 DNS 核对后再加入 IPv6。
- 记录 api.dgqfl.xyz 原始健康和就绪状态、服务地址及已有站点行为，用同样方法比较发布后结果。现有 API 代理、后端和数据库各自独立处理。
- 确认 Nginx 工作进程有官网路径读取权限。按下文准备独立日志目录并验证轮转。生产证书、密钥和其它站点配置使用现有受保护路径。
- 核对备案号、运营主体与域名的实际登记。小程序码和联系方式按运营方实际提供内容配置。通过真实微信确认入口和实际开放功能。

## 经人工确认后的发布顺序

### 官网访问日志

模板将官网日志写入 `/var/log/dgqfl-website/`。目录属主为 root，属组为现场实际的 Nginx 工作进程组，权限设为 0750，以便工作进程在收到 reopen 信号后访问文件。创建 `access.log` 与 `error.log` 并设为 0600。将 logrotate 模板安装至系统日志轮转目录，确认实际 Nginx 可执行文件和 PID 配置与 `postrotate` 的 reopen 命令对应。若服务器还有旧版官网日志，分别核对其原保留期限、权限与归档位置。

默认按日轮转，常规保留 186 天。用 `logrotate -d /etc/logrotate.conf` 检查独立规则已纳入每日任务，测试 Nginx reopen 后仍写入新文件。上线时核对访问日志确实省略查询参数，并核查代理、备份等是否有额外副本。依法需延长留存的记录须隔离保存，限制访问并在义务结束后清理。

### 站点切换

1. 备份原站点配置、启用链接及当前官网文件。记录备份位置、配置权限、原站点状态和原 current 指向。备份放在公网根目录之外，保留所有旧版本。
2. 将完整部署归档和校验文件上传到约定的临时目录。以 V1.3.1 为例，先运行 `sha256sum -c dgqfl-website-1.3.1-deploy.tar.gz.sha256`，解开外层归档后运行 `sha256sum -c dgqfl-website-1.3.1.tar.gz.sha256`。校验通过后在 `/srv/dgqfl-website/releases/` 下建立专属版本目录，仅将内层静态归档解压进去。首次部署时核对 `/srv/dgqfl-website/current` 的归属。
3. 配置官网专属虚拟主机。保留现有 Nginx 全局配置、API 虚拟主机及默认站点身份。用 nginx -t 检查语法、证书和重复名称警告。失败时恢复配置并停止切换。
4. 在 /srv/dgqfl-website/ 内创建指向本次版本目录的临时符号链接，在同一文件系统使用 mv -T 原子切换到 current。如使用已核验的其他绝对路径，同步调整站点 root。首次启用或配置有变更时对现有 Nginx 进行受控 reload。只更新静态内容的后续版本通常只需切换 current。
5. 先通过现场主机名和 TLS 核验再放量。生产检查包括 HTTP 到 HTTPS、HTTPS www 到根域、七条直接访问与刷新、未知路径 404、ICP备案链接、协议和隐私。记录手机与真实微信浏览器结果。复查原 API 的健康、就绪与已有访问行为。

## 回滚

- 只更新内容时，将 current 原子切回已记录的上一版，同样检查官网和原 API。
- 若调整过官网的 Nginx 配置，恢复本次备份的官网配置及链接，先执行 nginx -t，再 reload。
- 首次安装回退时，禁用并移走本次新启用的官网配置文件，恢复先前站点和链接。保留发布及备份记录。若本次同时批准过 DNS 修改，根据变更记录恢复并复核解析。

本次在隔离环境测试 Nginx 模板。生产主机、证书、DNS、发布与回滚待现场核验及人工确认。
