## 验收规则（每个项目均要有证据）

1. 418 个稳定项目 ID 逐项映射到明确通道，不允许静默落到默认类别。
2. 分类配置由后端下发并做准入校验：enabled、role、templateKey、schemaVersion、reviewPolicy、cityPolicy。
3. 用户进入项目能看到准确的入口状态：开放发布、商家认证后发布、官方查询、受限/暂不可用。
4. 实现发布项目：表单字段展示、必填及格式校验、存草稿、提交、后台审核、驳回原因、重新编辑、检索、详情、下架和举报。
5. 商家/机构及官方信息项目不得绕过核验直接发表；权威数据必须有来源与更新时间。
6. 审核并行权限控制：居民/商家/机构/管理员不同权限，服务端拒绝非法跨角色调用。
7. 空数据、网络错误、类目禁用、版本升级、重复提交、跨城检索都需覆盖自动化测试。
8. 每条 `categoryId` 对应的处理结果与测试证据写回台账，禁止凭页面能点击就标记完成。

## 本台账的关键语义说明

- 招聘分类中“全职岗位/兼职岗位”等本质属于用工形式，应作为筛选条件或发布快捷入口，而不是当作独立岗位类型。
- 家政维修“发布服务需求”和“商家提供服务”业务完全不同，不可共用同一张无身份校验的表单。
- 医疗、金融、殡葬、政务等仅建议接入受控目录或官方指引，具体开放能力应进行法务与平台规则评审。
- 项目当前有固定 `publications.type` CHECK 与服务端字段白名单，不可只修改前端映射；需同步调整后端编排和必要的数据表/迁移。
- 地图点位仅可由合规公开地址数据生成，不能把用户填写的私人地址自动转为公开坐标。
